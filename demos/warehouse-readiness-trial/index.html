Ready by 09:00?

A two-Skill field test for a warehouse migration. Define what “ready” means, then trace an eight-point drop in the first reporting window.

01 / Design KPIs

Set the cutover gate

At the weekly migration review, the warehouse owner and BI lead decide whether to migrate the next dashboard cohort. The pilot covers the dashboard-days scheduled in each complete Monday–Friday window.

Outcome · On-time dashboard readiness

Definition. Scheduled dashboard-days with a Gold refresh completed and validation passed by 09:00 SGT, divided by all scheduled dashboard-days. Missing status counts as a miss. Exclude only dashboard-days removed from the schedule before the window opens. Count each dashboard once per scheduled day and weight by dashboard-day.

Source and ownership. The warehouse owner maintains the schedule, refresh audit and validation contract. The BI lead reviews the dashboard rollup. A production implementation would left-join one canonical refresh status per dashboard-day to the frozen schedule.

Provisional gate. 95% for the next pilot week. The baseline was 96/100 and the current window was 88/100. At the same volume, recovering seven misses would reach 95%. Six misses cluster in one feed, so the pilot also needs at least one recovery elsewhere. This is a low-confidence planning threshold pending a second rehearsal and a confirmed recovery plan.

Drivers · Upstream delivery and Gold processing
  • Upstream delivery by 08:30. Scheduled dashboard-days with all required Silver inputs received by 08:30 divided by scheduled dashboard-days. Use the dependency map and ingestion audit. Data Engineering investigates a drop.
  • Gold processing by 09:00 after timely upstream delivery. Timely-input dashboard-days whose Gold refresh completes by 09:00 divided by all timely-input dashboard-days. Use the Gold refresh audit. The warehouse team investigates a drop. Always show the denominator alongside the rate.
Guardrails · Visibility and validation
  • Audit coverage. At least 99% of scheduled dashboard-days must have a recorded outcome. Count populated outcomes against the frozen schedule. A missing record still counts as a readiness miss.
  • Critical validation failures. Zero critical failures among completed refreshes, from the validation log. Show refresh coverage and hold the next wave if checks are missing or a critical failure is recorded.

Guardrail thresholds are pilot assumptions. The sample below demonstrates audit coverage, while critical failure counts and full driver telemetry would come from the validation and timestamp logs.

Tradeoffs · Alternatives and measurement checks

Average job duration can improve while the slowest dashboards miss opening time. Dashboard usage depends on adoption and does not isolate migration health. On-time readiness reflects the deadline the team controls, but equally weighted dashboard-days can mask a single critical dashboard. Review the critical dashboard list before each wave.

Before production use, reconcile the dashboard totals to the refresh audit, test duplicate and absent records, verify cutoff conversion to SGT, and agree on the critical dashboard list and exception policy.
